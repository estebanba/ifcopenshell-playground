# ifcopenshell-playground

Experiments with IFC (BIM) models in Python using [IfcOpenShell](https://ifcopenshell.org/), `ifccsv` and pandas, and with driving Blender/Bonsai and CADCraft from Claude over MCP.

## Setup

Requires [uv](https://docs.astral.sh/uv/) and Python 3.12.

```bash
uv sync
```

Open the notebooks in VS Code or Jupyter and select the `.venv` kernel.

Notebook outputs are stripped on commit by [nbstripout](https://github.com/kynan/nbstripout). The `.gitattributes` file is committed, but each clone needs the git filter registered once:

```bash
uv run nbstripout --install --attributes .gitattributes
```

## Models

IFC files are **not** committed (see `.gitignore`). Put them in `models/`:

- `AC20-FZK-Haus.ifc`: the KIT FZK-Haus sample model, available from the [KIT IFC examples](https://www.ifcwiki.org/index.php?title=KIT_IFC_Examples)
- `empty_model.ifc`, `model_with_wall.ifc`, `new.ifc`: created by `01-hello-world.ipynb`
- `blender_edit.ifc`: FZK-Haus edited in Bonsai over MCP: one thermal value changed, and a barrel roof with its structure rebuilt to match. It was made interactively, so no script regenerates it. Keep a copy. See [docs/fzk-haus-bonsai-edits.md](docs/fzk-haus-bonsai-edits.md).
- `casa-ato.ifc`: an approximate model of Casa ATO (IR arquitectura, San Isidro, 2016-2020), generated by `uv run python scripts/build_casa_ato.py`.
  - **Sources:** there are no drawings. It's reconstructed from the project text and photos (estebanbasili.com, ArchDaily; photos by Fernando Schapochnik).
  - **Dimensions:** estimates, roughly ±15%, set as constants at the top of the script.
  - **MEP:** a schematic design from `scripts/casa_ato_mep.py`. It's a proposal, not as-built: the systems are connected through ports and grouped into 15 `IfcDistributionSystem`s.
  - See [docs/casa-ato-model.md](docs/casa-ato-model.md).
- `*.blend`: Blender scene files saved next to the models. They hold viewport state only; the IFC is the source of truth.

- `sample_apartment.ifc`: an interior model of the apartment in `drawings/sample_apartment.dwg`. It's generated from the live CADCraft drawing with `uv run python scripts/build_sample_apartment.py --live`, and includes rooms, walls, doors, windows, floors, ceilings and furniture. Plan dimensions are exact. Heights are assumptions (ceiling 2.70 m), and furniture types marked "?" are guesses.

## Blender MCP

Tested with Blender 5.2.3 LTS, Bonsai 0.9.1 and [mcp-for-blender](https://github.com/ahujasid/mcp-for-blender) 2.2.7.

- The server is registered in `.mcp.json`. It is pinned to 2.2.7, runs with telemetry and update checks off (`DISABLE_TELEMETRY`, `BLENDERMCP_NO_UPDATE_CHECK`), and connects to Blender on `localhost:9876`.
- To install the add-on:

  ```bash
  uvx mcp-for-blender==2.2.7 install-addon --addons-dir "$HOME/Library/Application Support/Blender/5.2/scripts/addons"
  ```

  Then, in Blender:
  1. Enable **Interface: MCP for Blender**.
  2. Leave **Allow Telemetry** off and **Bind Address** set to `localhost`.
  3. Click **Start MCP Server**.

The add-on's socket has no authentication, and connected clients can run any Python inside Blender. Keep it on localhost and stop it when you're not using it.

## CADCraft MCP

[CADCraft](https://github.com/storytold/cadcraft) is a free, open-source (MIT OR Apache-2.0) 2D drafting app in the AutoCAD style. It reads and writes DXF and DWG. Here it's the drawing tool for interior design: you draft plans in CADCraft, and Claude reads them live over MCP and models them in Blender/Bonsai. The design is in [docs/cadcraft-interior-workflow.md](docs/cadcraft-interior-workflow.md).

Tested with CADCraft 0.19.0 on macOS.

1. Install the app (`cadcraft-<ver>-macos-universal.dmg`) and the CLI (`cadcraft-cli-<ver>-macos-universal.zip`) from the [releases page](https://github.com/storytold/cadcraft/releases). Check both against `SHA256SUMS.txt`.
2. Put the CLI on your PATH. This setup uses a versioned folder and a symlink:

   ```bash
   mkdir -p ~/.local/opt
   cp -R cadcraft-cli-0.19.0-macos-universal ~/.local/opt/cadcraft-cli-0.19.0
   ln -sfn ~/.local/opt/cadcraft-cli-0.19.0/cadcraft-cli ~/.local/bin/cadcraft-cli
   ```

3. Start the app with its control port:

   ```bash
   open -a CADCraft --args --control 7979
   ```

   A normal launch has no control port, so the MCP bridge has nothing to connect to.
4. The `cadcraft` server in `.mcp.json` runs `cadcraft-cli mcp --connect 127.0.0.1:7979 --lazy`. `--lazy` lets Claude Code start before the app is open. Approve the server the first time Claude Code asks.

The control port listens on loopback only. Each request has to carry a per-session token, which the app writes to `~/.cache/cadcraft-control-7979.token` (owner-only), and the bridge reads it by itself.

To read or render a file without the app:

```bash
cadcraft-cli info drawings/plan.dwg                 # summary as JSON: layers, blocks, counts, extents
cadcraft-cli convert drawings/plan.dwg /tmp/plan.png # render (also svg, pdf, dxf, dwg)
cadcraft-cli mcp                                    # headless MCP session (use the `open` tool)
```

The app updates itself (it went from 0.18.0 to 0.19.0 on first launch). It's not known yet whether that can be turned off.
